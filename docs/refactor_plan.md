# 共通解析・最適化コードの段階的リファクタ計画

この計画は**作業仕様**であり、記載した移行先モジュールが既に実装されていることを意味しない。各段階は専用PR、実行したテスト、PR CIで完了判定する。Phase 2限定。

## R0 — 互換性と比較基準の固定（次のPR）

- リポジトリの公開API、G1のチェックポイント形式、現在のP4-A生成ルールをスナップショットとして記録。
- LPF-007/008を共通MNAに読み込む際の接続ノード、部品Q、チップの物理列、結合行列、6設定可変C、UL/DL/H2/H3の最悪点について**ゴールデン回帰テスト**を追加。
- 既存P4-A 1/2シャードの実行・再開と、候補JSONの検証スクリプトを保持。`design_constraints.json`と`bands.csv`は改定しない。
- 監査済みのLPF-007基準値は [比較基準](baselines.md) を参照。古いノード番号体系との混同を防ぐ。

## R1 — 共有モデルと可変Cの配置一般化

- 正規化グラフ、固定L/C枝、指定ノードへの2枝以内の可変GND-C、物理チップ列・符号付き磁気結合を表す公開データ契約を導入。
- 旧`build_grounded_settings`が使うIN/OUT可変Cをデフォルト動作として維持し、追加APIで任意有効ノードへ接続可能にする。新旧両方の単位テストを付ける。
- LPF-007/008が汎用モデルで再現可能になることを優先し、回路グラフの枝数と内部ノード数、可変Cノード割当をチェックする。区別すべき物理配置の誤正規化をテストする。
- 仕様・部品・Q・面積・結合制約の重複ハードコードを、仕様読込＋明示的なモデルバージョンと検証に移行する。ソルバの計算結果が変更されないか照合する。

## R2 — 探索起源に依存しない評価と最適化API

- `matching_only` / `full_lpf`を混在させない統一評価契約。6設定UL/DL最大IL、H2/H3全区間最小減衰、最悪周波数、独立照合、電力収支を返す。
- 共通最適化インターフェースに変数境界、制約、seed、評価回数、収束、検証用グリッドを渡す。SLSQPを基準として、後段でepigraph minimax、継続法、適応周波数グリッドを比較可能にする。
- ChatGPT専用高速ソルバから共通候補形式へ変換するアダプタ、汎用探索への初期値引き渡し、独立MNAでの再検証を実装する。
- 汎用アルゴリズムは段階的に`src/lpf/`へ移し、`experiments/`は実験設定とオーケストレーションに限定する。従来のimport、CLI、G1復旧を互換ラッパーで維持する。

## R3 — 探索範囲の網羅性・実験の再現性

- 固定枝グラフ、可変Cの配置、物理チップ列／強結合隣接、PCB相互結合の探索範囲を明示し、生成可能／除外／未実行件数と理由を報告する。
- 各シャードに`graph_id`、`placement_id`、`layout_id`、`start_id`を持たせ、探索起源に関係なく重複・欠落を検査する。物理配置と可変C接続点の違いをIDで区別する。
- 全変更をG1のrun ID再開・Artifact復元・設定ハッシュ整合へ反映する場合は、チェックポイントスキーマの互換性と移行方針を記録する。
- 高密度再計算・独立照合を合格した候補のみ、既存の最良解との比較レポートに昇格する。

## 禁止事項

- 参照している旧実験ファイルや候補JSONを一括削除・改名しない。
- コード移動を数値最適化の改善や探索完了として報告しない。
- P4-A（当面内部ノード≤4、固定枝≤8）の拡張を、承認済み物理制約の緩和として扱わない。
- 旧チェックポイントを無検証で新スキーマへ読み込まない。
- Phase 3のスイッチC離散化、Ron/Coff、実装開発を開始しない。

## 完了レポートの必須項目

コード差分、変更前後のAPI対応表、物理制約差分（ゼロであること）、ゴールデン候補の評価値・許容誤差、独立解析、ユニットテスト・CI、実際に実施したActionsのrun ID、未完了範囲。
