# コード構成と探索方式の分担（Phase 2）

> 現行方針。2026-10-11時点の実装済み機能と、これから実装する構成を区別する。RF制約の正本は `data/design_constraints.json`。本書は物理制約を変更しない。

## 基本原則

**ChatGPT主導の回路考案と、スクリプト主導の体系的なトポロジー探索は並行して進める。** どちらも同じ回路表現、性能指標、制約検証、候補記録を使用する。片方にしか存在しない回路を、もう片方の探索結果だけで「劣る」と判定しない。

- **ChatGPT主導（仮説探索）**: 物理的な損失要因、ブリッジ、シャント共振器、伝送零点、磁気結合等に着目してトポロジーを提案。回路構造の知識を利用した専用・縮約ソルバで迅速に素子値を最適化。発見した良好解を共通形式で保存し、汎用ソルバで独立照合する。
- **スクリプト主導（探索範囲を宣言した体系探索）**: 有限のノード・枝・コスト制限内で回路グラフ、固定素子種別、可変C接続点、配置、結合候補を生成・枝刈り。多数の候補を段階的に最適化。生成・選別・最適化の対象件数と未探索範囲を記録する。構造列挙の網羅性と連続素子値の大域最適性を混同しない。
- **共通検証**: 6設定すべてのUL/DL最大ILとUL H2/H3最小減衰、結合行列正定値、受動性・電力収支、可変Cの設定間整合、コスト・素子制約を確認。候補と算出根拠は探索起源によらず共通の証拠レベルで比較する。

### 目標パッケージ境界（未実装を含む）

`src/lpf/`の下に、**graph / circuit model、components・policy、evaluation、topology generation、optimization、validation、result schema**の再利用可能な責務を揃える。モジュール名やディレクトリの確定は、公開APIを使う回帰テストを付けてから行う。

1. **モデル**：0=GND、1=IN、2=OUT、3以降=内部ノードのグラフ表現を使用。各L/C枝の接続、値、Q、物理チップ列、結合の極性、2枝以内の可変IC Cの**任意の対GND接続点**を保持する。異なる物理配置・可変C接続点は同じ無条件の「等価グラフ」と扱わない。
2. **解析**：汎用MNAを正本とし、独立節点解析と物理量検証を維持。構造が数学的に許す場合の高速等価回路解析はオプション実装とし、独立MNA照合の後に採用する。
3. **最適化**：`matching_only`（6設定UL/DL最大IL）と`full_lpf`（これにH2/H3の全区間制約を追加）を明示。予算・乱数シード・収束・評価回数・最悪周波数・検証グリッドを返す。ChatGPT専用ソルバと汎用最適化器の両方に同じ候補／結果契約を適用する。
4. **生成と列挙**：生成済み・重複除去済み・枝刈り・未実行・最適化失敗を分けて計数する。固定グラフ構造と、可変Cノード選択・磁気結合可能なチップ物理列／符号は別の探索次元として保持する。
5. **結果**：探索起源（`ai_hypothesis` / `enumerated` / `mutated`）、設計仕様ID、目的関数、結果の確認レベル、コードSHA、設定・グリッド・依存バージョン・種・収束・チェックポイントを記録する。`best_found`を性能限界と呼ばない。

## 最優先の相互運用ギャップ

現在の `experiments/matching_limit/instantiate_graph.py:build_grounded_settings` は6設定の可変Cを**入力と出力の対GND**に固定している。LPF-007/008の可変Cは、これとは異なる**内部シャントLCトラップ節点**にある。現行P4-Aだけでは先行の有望候補を表現・改善する公平な比較にならない。

**最初のリファクタで必須**：任意の有効ノードを可変Cの対GND接続点に選び、各設定のC値だけが変化することを保証する。LPF-007/008を汎用モデルに変換し、保存済みの応答を共通MNAで再現する回帰テストを実装する。B13+B14は同一設定とする。可変Cの枝数は原則2以内のままとし、変更は探索可能範囲の拡張であって物理制約の緩和ではない。

**P4-Aの枝数**は当面、生成対象の固定L・固定C枝について最大8本と定義する。可変IC-C（最大2枝）は別に数える。新しい枝数定義で既存P4-Aの結果を無言で再分類しない。内部ノードはGND/IN/OUTを除いて最大4個。

## 移行の進め方

- **互換性優先**：既存の`p4_batch.py`、G1シャードID・チェックポイント形式・GitHub Actionsを破壊しない。既存APIを保ったまま、新しい共通モジュールをテストで固定し、旧パスを薄いラッパーに移す。
- **コード移動とアルゴリズム変更を分離**：機能等価なコード移動 → 回帰テスト → 性能改善 → 新探索、の順とする。最適化結果の数値差は明示・比較する。
- **物理制約の正本を一元化**：Q、コスト、部品上限、結合限界を複数ソースで別々に定義しない。既存ソースに埋め込まれた定数の統合は実装とテストが必要であり、現時点で完了したとは主張しない。
- **研究記録を保持**：`experiments/`の日時付きファイル、`data/`の候補・チェックポイント・証拠は参照が切れないように残す。古い計画文書は現行ロードマップへ誘導し、履歴を削除しない。
